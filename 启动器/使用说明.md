# AML · 使用说明

## 它是做什么的

游戏本体放在 U 盘 `Games\` 里，存档也放在 U 盘 `Data\` 里。启动器在开游戏前，把本机原本的存档目录替换成一个指向 U 盘的通路（目录联接），游戏照常读写本机路径，实际数据实时落在 U 盘上。换一台电脑插上 U 盘，存档跟着走。

- 不需要改游戏、不需要装驱动、不需要管理员权限（首次接管个别系统目录时除外）。
- 每台电脑只接管一次，之后每次启动自动重建，U 盘换盘符也能自动恢复。
- 联接失败会自动降级成"复制模式"，保证游戏能玩、存档能带走。

## 快速开始

1. 把整个 `启动器` 文件夹放到 U 盘根目录（和 `Games` 同级）。
2. 游戏文件夹放进 `Games\`，例如 `Games\PvZ\PlantsVsZombies.exe`。
3. 双击 `启动器.vbs` 打开启动器窗口（不会闪黑框）；新游戏点「添加游戏」「学习存档」，老游戏直接点「启动」（或双击卡片）。
4. 玩完关掉游戏，等窗口底部提示“…已结束”再拔 U 盘。

命令行也可以：

```
启动器.cmd PvZ          直接启动
启动器.cmd -List        列出游戏
启动器.cmd -Console     文字菜单（没有图形环境时用）
```

## 单文件 exe（可选）

`dist\AML.exe` 是把整个启动器运行时打进去的单文件，约 76 KB，可以单独拷到 U 盘根目录双击运行：

- 第一次运行会在 exe 旁生成 `Launcher\.runtime\v<版本>\`（内置运行时）、`Launcher\config.ini`，以及 `Games\`、`Data\`、`Backups\`、`Snapshots\`、`Logs\` 这些目录；以后直接启动，不会重复解压。
- 如果你已经有完整的 `启动器\` 文件夹，把 `AML.exe` 放进去就行——检测到旁边的 `Launcher\Start.ps1` 会直接用它，不再生成 `.runtime`（混合模式）。
- 升级：换新的 `AML.exe` 覆盖即可，旧版本运行时会被自动清理。
- 解压坏了或想强制重来：`AML.exe -Repair`。
- 未做代码签名，首次运行 SmartScreen 可能提示，点「更多信息 → 仍要运行」。
## 图形界面

窗口分左右两块：

- 同一时间只允许一个启动器窗口；重复双击 启动器.vbs 会直接把已有窗口激活到前面。
- 顶部：标题、U 盘路径、游戏数量，右侧「刷新」「添加游戏」「打开 Games」「设置」「置顶」（窗口总在最前，状态记在 `config.ini` 的 `topmost`，下次打开保持）。
- 左侧详情区：当前选中游戏的图标（右键可换图标）、名称（名称右侧的小铅笔点开重命名）、模式与上次运行时间；下面是实时日志（最近 200 行，自动滚到底）。
- 左侧按钮随配置变化：
  - 有独立启动器：大按钮「拉起启动器」，下面并排「直接启动」「打开存档位置」，再下面「学习存档位置」；
  - 没有启动器：大按钮「启动游戏」，下面并排「打开存档位置」「学习存档位置」。
- 右侧列表：每个游戏一张卡，只显示图标、名称、exe 文件名和状态（`● 就绪` / `● 缺少 exe`），不放启动按钮。单击选中，选中的卡会自动排到所有卡片最上面；双击直接启动。
- 没启动游戏时，左侧只显示图标、名称和按钮（图标/名称位置偏下、不显示日志）；点启动后，图标和名称会向上收，日志区展开，按钮变成「运行中」；游戏退出后再动画退回初始状态。
- 卡片之间和窗口两侧都留了间距；底部状态栏显示最后一条状态，右侧「打开日志」直接打开当天日志。
- 快捷键：F5 刷新，Esc 关闭窗口。关窗口不会中断正在运行的游戏——后台启动器会继续等游戏退出并回写存档。
- 卡片右键：启动、直接开始、置顶卡片 / 取消置顶卡片、学习存档位置、存档位置…（手动查看/修改映射）、更换图标、恢复默认图标、还原到本机、卸载游戏、打开游戏文件夹。
- 置顶卡片：卡片右侧有一个图钉图标，点它即可置顶/取消置顶（也可右键选「置顶卡片 / 取消置顶卡片」）。置顶的卡片永远排在列表最上面（按名称排），图钉变紫、卡片边框高亮并有淡紫光晕，状态栏会提示。窗口置顶（顶部「置顶」按钮）与卡片置顶是两件事。

## 设置

点顶部「设置」打开对话框，改的是整台 U 盘的全局配置（写回 `Launcher\config.ini`，下一次启动生效）：

- 接管模式：自动（优先联接，失败降级复制）/ 只联接 / 只复制；
- 快照保留份数、单次快照上限 MB；
- 排除目录：逗号分隔，快照和复制时任何层级的同名目录都会跳过（缓存、日志等）；
扫描排除/跳过名单不在这个对话框里改，统一放在 `Launcher\scan-lists.ini`（右下「打开名单…」可直接打开）：`[exclude]` 里一行一个文件名关键字，`[skip_dirs]` 里一行一个目录名，`[include]` 是反向白名单（名字像工具/安装包、但确实是游戏主程序的 exe 写这里，强制当游戏列出）。保存后下一次扫描生效，只影响「添加游戏」时列出什么，不影响已建好的游戏。

除了界面上的几项，`config.ini` 里还有两个保留项：`log_keep_days`（日志保留天数，默认 14）和 `backup_keep`（每个游戏接管前备份保留份数，默认 3），启动时自动清理更早的。

设置只影响之后的新启动；已经建好的联接不会被打断。

## 背景壁纸与透明度

- **背景壁纸**：设置 → 背景壁纸 →「浏览…」选一张图，会复制成 `Launcher\wallpaper.*`，跟着 U 盘走；不想用了点「清除」。
- **壁纸透明度**：0 = 只看到底色，100 = 原图。默认 60，压暗一点标题更好读。
- **卡片透明度**：左侧详情卡、右侧游戏卡、底部状态栏共用这一个值（20–100），100 = 完全不透明；默认 92。
- 壁纸会被等比裁切铺满窗口，顶部自动压一层深色渐变，保证标题和按钮可读。
## 游戏图标

- 每张卡默认自动用游戏 exe 的图标；第一次显示时提取并缓存到 `Launcher\icons\<游戏id>.png`，跟着 U 盘走。
- 想换：右键卡片「更换图标…」，选 png / jpg / bmp / ico，启动器会居中裁成方形存成 64×64。
- 想恢复：右键「恢复默认图标（从 exe 提取）」。
- 图标只影响启动器里的显示，不改游戏文件。

## 卸载游戏

右键卡片「卸载游戏…」：

- 默认勾选「先把 U 盘存档还原到本机（并删除 U 盘副本）」——等价于先做一次「还原到本机」，再删 U 盘副本；
- 会删掉 `Launcher\profiles\<id>.ini` 和这个游戏的图标缓存；
- 游戏文件默认保留在 `Games\` 下；想一起删就勾「同时删除 Games\ 下的游戏文件（不可恢复）」；
- 卸载后重新把游戏加回来，用「学习存档」重新认一次存档位置即可。

## 已经配好的游戏

- **PvZ 杂交版 0.32**：已在 `Games\PvZ杂交版\`，profile 也写好了，直接选它就能玩；存档在 `Data\PvZ杂交版\godot`。
- **PvZ 原版/其他改版**：把游戏文件夹放进 `Games\PvZ\`（文件夹名对应 `Launcher\profiles\pvz.ini`），exe 用 `PlantsVsZombies.exe` 或 `PvZ.exe` 都行。
- 启动器只列出 `Games\` 下**找得到 exe** 的文件夹；空文件夹不会显示。

## 学习存档（不用手写配置）

新游戏可以直接让启动器自己找存档位置：

1. 把游戏文件夹放进 `Games\`，点「刷新」；
2. 卡片上点「学习存档」→「开始学习」；
3. 照常玩，**进游戏存一次档**，然后完全退出游戏；
4. 等状态变成「分析完成」，列表里是刚才新增或变大的目录（按得分排序，一般第一个就是）；
5. 勾选真正的存档目录，点「保存并关闭」。

保存后会在 `Launcher\profiles\<游戏id>.ini` 里追加 `[mapping.N]`，再点「启动」就自动接管。

注意：

- 只对**还没接管**的游戏有效。已经接管过的游戏，本机存档目录已经是联接，学习看不到变化（数据在 `Data\` 里）。
- 日志、缓存、临时目录、浏览器数据已经排除；注册表学习暂未开放。
- 第一次「开始学习」会扫一遍常用目录（2~3 万文件约 3~5 秒），游戏退出后再扫一遍并对比。
- 勾选父目录和子目录不会重复：保存前会自动去掉被包含的子目录。
- 分析结果为空：可能游戏还没写盘、存档在排除目录里，或只写了注册表。

## 存档位置（手动查看/修改）

自动学习不一定次次准，或者游戏更新后把存档换了地方——这时手动改：

1. 在卡片上**右键 →「存档位置…」**；
2. 列表里是当前这个游戏的所有映射：类型（目录/文件）、原位置、目标位置、状态（联接 / 原位置目录 / 不存在）；
3. 选中一条，点「修改…」：
   - **原位置**：可以写 `%APPDATA%\...` 这类变量，也可以写绝对路径，点「浏览…」选目录或文件；
   - **目标位置目录名**：存档在 `Data\<游戏id>\` 下的子目录名，改名等于换一份独立的存档（老数据还在原目录，不会删）；
   - **模式**：继承全局 / 只联接 / 只复制——想给单个游戏单独用复制模式，就在这里改；
4. 点「保存」立即写回 `Launcher\profiles\<游戏id>.ini`，**不用重新学习**，下次点「启动」就按新路径接管。

其它按钮：

- 「定位原位置」「定位目标位置」：直接开资源管理器看两边内容；
- 「添加…」：手动加一条映射（原位置 + 目标位置目录名），适合学习模式没找到的情况；
- 「删除」：拆掉联接（数据仍留在目标位置的 `Data\` 里）并删掉这条配置。

注意：改了原位置后，旧的联接会被自动拆掉；数据不会删，仍在目标位置里，需要的话手动搬。

## 添加一个新游戏

最简单的方法是用向导：

1. 把游戏文件夹放进 `Games\`（也可以放 U 盘其他目录，见下一节）；
2. 点顶部「添加游戏」→「浏览…」选这个文件夹（或直接粘路径）→「扫描」；
3. 下拉里会自动选最像主程序的那个 exe，可以手动改；有独立启动器的，勾上「这个游戏有独立的启动器」再选启动器 exe（会自动选中名字里带 launcher/start/play 的那个）；
4. 确认显示名称和标识，点「创建游戏」；
5. 弹出「现在学习它的存档位置吗？」选「是」，就接着走学习流程；选「否」以后也能在卡片上点「学习存档」。

向导只写 `[game]` 段（`name` / `exe` / `launcher` / `launcher_args` / `wait=process`），不猜存档；存档仍然用「学习存档」或手写 mapping。

### 文件夹里 exe 很多怎么办

大型游戏目录里常有 `unins000.exe`、`updater.exe`、`crashreport.exe`、`UnityCrashHandler64.exe` 这类工具，向导会自动把它们藏起来，列表里只留：

- `(游戏) …`：游戏本体；
- `(启动器) …`：名字带 launcher / start / play / run / boot / login 的启动器。

默认选中第一个「游戏」；勾「这个游戏有独立的启动器」后，启动器下拉会自动选第一个「启动器」。

确实要选被藏起来的工具时，勾右下「显示工具/卸载类 exe」，它们会以 `(工具) …` 出现，创建时还会再确认一次。扫描最多下探三层目录，`redist`、`vcredist`、`installer`、`tools` 这类子目录直接跳过。

内置名单之外，还可以在 `Launcher\scan-lists.ini` 里加自己的排除关键字和跳过目录；比如育碧那种 `games\<游戏名>\<游戏>.exe` 的结构，把 `games` 写进 `[skip_dirs]`，扫描结果就只剩启动器，不会把每个游戏都列出来。名单只按文件名/目录名做正则匹配，纯本地、不需要联网，也不依赖任何 AI。如果某个游戏主程序被内置规则误判成工具，把它写进 [include] 段即可强制显示为游戏。

手写配置也可以：文件夹名就是游戏 id，例如 `Games\Stardew Valley\`，在 `Launcher\profiles\` 下新建 `<游戏id>.ini`，写一条 mapping。

最小配置（自动找 exe，接管一个存档目录）：

```ini
[game]
name=星露谷物语
exe=Stardew Valley.exe

[mapping.1]
kind=dir
local=%APPDATA%\StardewValley
store=appdata
```

要点：

- `local` 支持变量：`%APPDATA%`、`%LOCALAPPDATA%`、`%USERPROFILE%`、`%DOCUMENTS%`、`%SAVEDGAMES%`、`%PROGRAMDATA%`、`%GAMEDIR%`（游戏目录）、`%ROOT%`（U 盘启动器根目录）。
- `store` 是 U 盘上的相对目录，实际位置 `Data\<游戏id>\<store>`。
- 一个游戏可以有多条 mapping，编号连续：`[mapping.1]`、`[mapping.2]`……
- 存档是单个文件而不是目录时，用 `kind=file`。
- 这个游戏不需要接管时，profile 里不写 mapping 即可，启动器只负责启动。
- 游戏自带 launcher、或者 launcher 拉起游戏后自己退出，用 `wait` 指定等谁（见下一节）。
- 找不到存档位置时，先启动一次游戏、玩到产生存档，再用卡片上的「学习存档」看哪些目录刚被写过。

## 游戏不在 Games\ 里（U 盘其他目录）

游戏文件夹不一定非要放 `Games\`。比如 U 盘根目录已经有一个 `Games2\`，里面是解压好的融合版：

```
F:\Games2\植物大战僵尸融合版4.1\PlantsVsZombiesRH.exe
```

用「添加游戏」直接选这个文件夹就行，向导会在 profile 里写一条 `dir=`：

```ini
[game]
name=植物大战僵尸融合版4.1
dir=F:\Games2\植物大战僵尸融合版4.1
exe=PlantsVsZombiesRH.exe
wait=process
```

- `dir` 可以写绝对路径，也可以写相对启动器根目录的路径（比如 `Games\PvZ`）。
- 启动器列游戏时，除了扫 `Games\` 的每个子文件夹，也会读 `Launcher\profiles\*.ini` 里带 `dir=` 且目录存在的配置。
- 存档仍然按 `local` 接管，跟游戏本体放在哪无关；换台电脑只要这个路径还在（U 盘插着、盘符没变）就能直接玩。

## 换电脑 / 换盘符

存档联接里记的是**绝对路径**（`F:\启动器\Data\...`），所以换盘符后旧联接会指向不存在的位置。启动器每次启动都会：

1. 发现本机存档目录还是个联接、但目标已经不在；
2. 自动拆掉旧联接，按当前启动器所在位置重建（日志里会写「版本隔离：… 原指向 H:\…，切换为 F:\…」）；
3. 游戏照常读写，存档仍是 U 盘里的那一份。

实测：把 `F:\` 用 `subst H:` 映射后从 `H:\启动器` 启动，联接切到 `H:\...`；删掉 subst 再从 `F:\启动器` 启动，自动重建回 `F:\...`，不需要手动改任何配置。

换电脑时唯一要注意的是：U 盘插上后盘符如果变了也没关系，**从新盘符打开启动器**就会自动重指；但不要在旧联接还指着旧盘符时运行游戏本身（那时存档目录是空的），先开启动器再点「启动」。

## 游戏自带启动器

有些游戏（尤其社区离线版、带更新器的网游）启动的是 launcher，再由它拉起真正的主程序；launcher 可能拉起游戏后自己立刻退出，也可能长期驻留托盘。

从 v0.6 起，启动器和主程序分开写：

```ini
[game]
name=某离线版
exe=Game.exe            ; 真正的主程序，「直接开始」和 wait=name 用它
launcher=Launcher.exe   ; 启动器，可留空
launcher_args=          ; 传给启动器的参数（可留空）
wait=tree               ; 只在「直接开始」时按这个等
```

- 卡片主按钮「启动」：有 `launcher` 就拉启动器，并**强制按进程树等待**（启动器退出、它拉起的游戏也退出才收尾），不吃 `wait`；没有 `launcher` 就直接起 `exe`。
- 卡片「直接开始」：跳过启动器，直接起 `exe`，按 `wait` 等。
- 学习存档时，如果有启动器，会多一行「启动方式：直接启动游戏 / 经启动器」，默认直接启动；想学到启动器写的东西就选「经启动器」。

`wait` 的取值（只影响直接启动 / 无启动器时）：

| wait | 等到什么时候 | 适用 |
| --- | --- | --- |
| `process`（默认） | 游戏进程退出 | 游戏本身就是单进程 |
| `tree` | 游戏和它拉起的整棵进程树都退出 | 游戏会拉起子进程，或常驻托盘 |
| `name:游戏主程序.exe` | 等指定进程出现，再等它退出 | 知道主程序名时最稳 |
| `none` | 启动后立即返回 | 纯绿色、只读启动器 |

老写法（没有 `launcher`，把启动器直接写在 `exe`）仍然兼容：这时主按钮就是起启动器，`wait` 按表里的规则等它，例如 `exe=Launcher.exe` + `wait=name:Game.exe`。新配置建议用 `launcher=` 分开写。

- `tree` / `name:` 用 Windows Job Object 跟踪进程树，几乎不占 CPU；拿不到 Job 时退回进程轮询。
- 复制模式强制使用 `tree`（写 `process` 会被自动改掉），否则游戏还没退出就把存档回写了。
- launcher 需要的工作目录、参数、管理员权限：`workdir`、`args`、`runas=1`。
- 很多离线版的 launcher 只做更新检查，直接把 `exe` 指主程序、`wait=process` 更省事。
- `args` 里带空格的路径要自己加引号；整串原样传给进程。

## 版本隔离（多个改版共用一个存档目录）

有些改版（PvZ 的各种杂交版、年度版）共用同一个本机存档目录，但存档内容互不兼容。启动器按"每个游戏一个独立 store"处理：

- `Games\PvZ原版\` → `Data\PvZ原版\programdata`
- `Games\PvZ杂交版\` → `Data\PvZ杂交版\programdata`

启动 A 时，本机目录的联接自动切到 A 的 store；换成 B 时再切回 B 的 store。两个版本各留各的存档，不会互相覆盖。

- 联接模式：切换只是重建联接，瞬间完成，两边数据都不动。
- 复制模式：切换前会先把本机目录里属于上一个游戏的改动回写到它的 store，再复制当前游戏的存档过来。归属记录在 `Launcher\state\<MachineGuid>.ini`。
- 第一次给"共用目录的第二个版本"建 profile 时，如果它还没被记录过归属，启动器按"本机旧档只备份、不合并"的规则处理，避免把别的版本的存档吞进新 store。

## 三种模式

在 `Launcher\config.ini` 里改：

| 模式 | 行为 |
| --- | --- |
| `auto`（默认） | 优先目录联接；建不了联接就自动复制 |
| `link` | 只允许联接，失败就报错 |
| `copy` | 不建联接，启动前把 U 盘存档复制到本机，退出后复制回去 |

单个游戏也可以在 mapping 里写 `mode=copy` 单独覆盖。

复制模式适合：游戏不认联接、目标目录在只读位置、或者你不想在本机留下任何联接。代价是每次启动/退出都要等复制，并且如果游戏崩溃，本次进度可能来不及回写（启动前会自动做快照）。

## 存档安全

- `Backups\<游戏>\<时间>\`：接管本机旧存档前的完整备份，只增不删。
- `Snapshots\<游戏>\<时间>\`：每次启动前的 U 盘存档快照，默认保留最近 5 份。
- 从没出现过"用本机旧档覆盖 U 盘新档"的情况：U 盘已有数据时，本机旧档只备份、不合并。
- 快照默认跳过 `shader_cache`、`logs`、`cache`、`temp` 这类缓存目录（`config.ini` 的 `exclude_dirs` 可改）。
- 单个游戏存档特别大时，可在它的 profile 里写 `max_snapshot_mb=2048` 覆盖全局上限；设 0 表示用全局值。
- 恢复：把 `Snapshots\...\` 里的内容复制回 `Data\<游戏>\<store>\` 即可。

## 还原到本机

卡片右键 →「还原到本机…」，把 U 盘上的存档复制回本机，并拆掉目录联接：

- 还原后这个游戏就像普通安装，存档写在本机；再点「启动」会重新接管、继续跟随 U 盘。
- 本机已有同名目录会先备份到 `Backups\`。
- 勾选「同时删除 U 盘上的存档副本」后，U 盘上的 store 会被删掉，这个游戏不再跟随 U 盘（适合把游戏从 U 盘撤下来）。
- 游戏运行中不能还原，先退出游戏。

## 常见问题

**U 盘换了盘符，或者换了一台电脑？**
启动器每次启动都会重建本机这一端的联接，指向当前的 U 盘路径。断掉的旧联接会被自动清理。

**提示"U 盘不可写"？**
检查 U 盘写保护开关、磁盘是否满了、或者杀毒软件是否拦截。

**游戏把存档写到了别的地方？**
说明 mapping 的 `local` 不对。用卡片上的「学习存档」自动找，或者手动看：玩一次游戏，然后看 `%APPDATA%`、`%LOCALAPPDATA%`、`Documents\My Games`、`Documents\Saved Games` 下哪个目录的修改时间变了。

**同一个游戏在两台电脑上路径不一样？**
每个游戏可以按机器写不同的 mapping，或者用 `%USERPROFILE%` 这类变量让路径自适应。

**想彻底撤掉？**
用卡片右键「还原到本机…」即可：拆联接、把存档复制回本机，可选删除 U 盘副本。`Backups` 里另有接管前的原始备份。

## 目录结构

```
U盘\
├─ 启动器.cmd
├─ Launcher\
│  ├─ Start.ps1
│  ├─ config.ini
│  ├─ lib\           启动器代码
│  ├─ profiles\      每个游戏一个 ini
│  └─ ui\
├─ Games\            游戏本体
├─ Data\             存档（真正跟着 U 盘走的数据）
├─ Backups\          接管前的本机存档备份
├─ Snapshots\        每次启动前的存档快照
└─ Logs\             运行日志
```
## 自检与已知限制

- 回归自检：powershell.exe -NoProfile -ExecutionPolicy Bypass -File "启动器\Tests\run-regression.ps1"，7 项检查全 PASS 才算正常（退出码 0）。
- 复制模式提醒：Launcher\config.ini 的 copy_warn_mb（默认 512）是启动前提醒的阈值，超过会弹窗确认。
- 已知限制：右侧游戏列表的滚动条仍是系统白色（WinForms 通用控件限制，已尝试 SetWindowTheme/uxtheme 无效）；游戏多时用滚轮或拖动。
## 窗口操作

- 启动器是无边框窗口：按住顶部空白处或标题「AML」可以拖动窗口。
- 右上角两个小按钮：— 最小化，× 关闭（关闭不影响正在运行的游戏，后台会继续等待并回写存档）。
- 窗口固定 1080×720，不提供拉伸和最大化；按 Esc 也能关闭。
